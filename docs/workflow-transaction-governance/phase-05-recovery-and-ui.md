# 阶段五：恢复、冲突与用户界面

## 目标

把事务事实和恢复选择以用户可理解的方式展示出来，同时保证系统不替用户做不可逆决定。

## 恢复流程

应用启动或 Run Center 打开恢复中的 Run 时：

1. 读取事务账本、快照、事件和外部 receipt；
2. 对 `applying`、`unknown` 和未完成补偿操作调用 inspect；
3. 生成恢复预览，不直接执行补偿；
4. 按事务事实展示继续、回滚到当前保存点、尽力全量补偿、保留现场和放弃处理；账本边界未知或保存点后存在外部操作时隐藏保存点回滚；
5. 用户确认后才创建恢复 attempt，并追加恢复事件。

“继续”只有在至少一个节点尚未完成，或存在待审批提交点，且没有未知操作、文件冲突或隔离工作区丢失时才可用。保存点回滚还必须先读取快照元数据和内容并完成差异检查；只有方法存在但材料缺失时不展示该动作。规则建议只能推荐当前预览实际列出的动作。

“尽力全量补偿”只对可补偿操作执行自动逆序恢复，并可同时回滚工作区。只要仍有 `applied` 的不可逆操作，最终状态必须是 `partially_rolled_back`，恢复建议必须列出对应 operationId 和人工核对步骤；不能因为文件回滚成功就显示为完全回滚。

Provider 无法自动 inspect 或仍返回 `unknown` 时，Run Center 提供“核验为已应用”和“核验为未应用”两种人工动作。用户必须填写远端记录、receipt 或人工检查依据；系统把 actor、时间、理由和核验结果写入操作账本，再刷新可用恢复动作。所有恢复、冲突和人工核验入口都把 actor 限制为 256 字符、理由限制为 2,000 字符，并在运行时与持久化边界再次校验，防止旁路调用写入无界审计记录。

同一 Run 的恢复、冲突、人工核验和刷新请求必须串行处理。只有公开 Run 已进入 `waiting_for_user`、`stopped` 或 `failed`，且旧执行租约已经释放后，恢复边界才允许修改 durable state；仍在执行的 Run 失败关闭。应用重启、恢复刷新和执行任意恢复动作前，都必须对全部 Workflow 变更路径重新执行三方检查，不能用公开 Run 的旧冲突列表覆盖实时结果；只有 transaction、节点集合、可用动作和三方文件摘要等完整恢复事实均未变化时，才允许继续展示上次 Manager 建议。工作区冲突检查或 operation ledger 无法读取时必须阻止“继续”，不能把不可读证据降级为空结果。

并行批次发生失败、暂停或 `unknown` 时，恢复页还必须列出：

- 已取消、正在取消和无法确认停止的节点；
- 每个并行节点的 operationId 和最后已知状态；
- 仍可能产生副作用的进程或外部请求；
- fail-fast 后没有启动的后续节点。

调度器在此期间不得继续发放新的节点任务。

## Manager Agent

Manager Agent 可以读取：

- 基线和当前文件 diff；
- 节点历史、工具调用和错误；
- 操作账本、receipt 和补偿能力；
- 三方冲突内容。

Manager Agent 可以生成：

- 推荐回滚目标；
- 逆序补偿计划；
- 冲突候选合并；
- 无法恢复项和人工步骤；
- 继续、回滚、保留现场的风险比较。

Manager Agent 不得未经用户确认：

- 写入真实工作区；
- 执行外部补偿；
- 发送消息；
- 修改提交点或事务状态。

## Run Center 展示

### Run 级

- 事务模式、事务状态、保存点/提交点；
- 基线建立后的受治理文件数和排除路径；
- 当前恢复阻塞项；
- 已提交、已补偿、状态未知和不可撤销操作数量；
- 快照保留期限；
- 最终报告下载和安全清理入口。

### 节点级

- 节点执行状态和完成结论；
- attempt 历史；
- changed paths；
- 工具调用失败和必需工具判定；
- 脚本退出码、stderr、超时和 effectState；
- 相关 operation receipt；
- 重试、继续、回滚和查看证据动作。

### 冲突页

展示三方：

```text
Workflow 基线 | Workflow 隔离结果 | 用户当前工作区
```

用户可以逐文件保留当前版本、采用 Workflow 隔离结果、手动合并，或查看 Manager Agent 候选结果。每次决定都必须带 actor 与依据，并绑定当时的当前文件摘要。选择当前版本或手动合并会改变隔离内容，因此最后一个冲突解决后必须用新内容摘要刷新 commit plan；只允许工作区步骤变化，外部操作步骤若漂移则停止并要求重新审阅。采用 Workflow 结果时若工作区证据发生意外变化，同样失败关闭。

## 审批交互

- 启动页选择 batch/per-operation；
- 高风险操作展示具体目标、参数、不可逆性和补偿能力；
- 动态新增操作使原授权失效；
- 自动提交授权失效条件必须可见；
- 必审提交点展示待审批 checkpoint、当前 plan digest、文件差异和外部操作；工作区证据包含路径和内容 hash，审批绑定该 digest，同一路径内容或操作变化后重新进入等待；
- 所有用户决定记录 actor、时间、依据和相关 operationId。

## 报告

报告包括：摘要、节点时间线、文件 diff、外部操作清单、脱敏且限长的请求与 receipt、按最终状态时间排列的补偿结果、未知项、用户决定、冲突和建议人工步骤。人工核验后刷新最新 operation 状态与核验依据，恢复动作后写入最新决定和补偿结果，多文件冲突的每次决定即时落盘；Manager 建议在展示和持久化前统一脱敏。报告写入 durable run state，重启后保留提交结果、真实 diff 和恢复决定；旧 Run 才从节点输出兼容重建。

## 验收

- 用户不打开日志也能解释 Run 为什么未提交；
- 任意未知项都有明确处理动作；
- Manager 候选结果不会绕过最终确认；
- 重启后恢复页和报告与之前一致；
- 已提交/已完全回滚 Run 的完整材料从最近一次事务活动起保留 7 天后按策略清理；最终提交、完整回滚、人工核验和恢复刷新都会续期。
