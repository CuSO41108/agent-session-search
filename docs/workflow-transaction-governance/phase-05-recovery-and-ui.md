# 阶段五：恢复、冲突与用户界面

## 目标

把事务事实和恢复选择以用户可理解的方式展示出来，同时保证系统不替用户做不可逆决定。

## 恢复流程

应用启动或 Run Center 打开恢复中的 Run 时：

1. 读取事务账本、快照、事件和外部 receipt；
2. 对 `applying`、`unknown` 和未完成补偿操作调用 inspect；
3. 生成恢复预览，不直接执行补偿；
4. 展示继续、回滚到保存点、尽力全量补偿、保留现场和放弃处理；
5. 用户确认后才创建恢复 attempt，并追加恢复事件。

并行批次发生失败、暂停或 `unknown` 时，恢复页还必须列出：

- 已取消、正在取消和无法确认停止的节点；
- 每个并行节点的 operationId 和最后已知状态；
- 仍可能产生副作用的进程或外部请求；
- fail-fast 后没有启动的后续节点。

调度器在此期间不得继续发放新的节点任务。

## Manager Agent

Manager Agent 可以读取：

- 基线和当前文件 diff；
- 节点历史、工具调用和错误；
- 操作账本、receipt 和补偿能力；
- 三方冲突内容。

Manager Agent 可以生成：

- 推荐回滚目标；
- 逆序补偿计划；
- 冲突候选合并；
- 无法恢复项和人工步骤；
- 继续、回滚、保留现场的风险比较。

Manager Agent 不得未经用户确认：

- 写入真实工作区；
- 执行外部补偿；
- 发送消息；
- 修改提交点或事务状态。

## Run Center 展示

### Run 级

- 事务模式、事务状态、保存点/提交点；
- 当前恢复阻塞项；
- 已提交、已补偿、状态未知和不可撤销操作数量；
- 快照保留期限；
- 最终报告下载和安全清理入口。

### 节点级

- 节点执行状态和完成结论；
- attempt 历史；
- changed paths；
- 工具调用失败和必需工具判定；
- 脚本退出码、stderr、超时和 effectState；
- 相关 operation receipt；
- 重试、继续、回滚和查看证据动作。

### 冲突页

展示三方：

```text
Workflow 基线 | Workflow 隔离结果 | 用户当前工作区
```

用户可以逐文件手动合并，或查看 Manager Agent 候选结果。最终写入前必须重新展示 diff 并确认。

## 审批交互

- 启动页选择 batch/per-operation；
- 高风险操作展示具体目标、参数、不可逆性和补偿能力；
- 动态新增操作使原授权失效；
- 自动提交授权失效条件必须可见；
- 所有用户决定记录 actor、时间、依据和相关 operationId。

## 报告

报告包括：摘要、节点时间线、文件 diff、外部操作清单、补偿结果、未知项、用户决定、冲突和建议人工步骤。敏感信息使用受限脱敏预览。

## 验收

- 用户不打开日志也能解释 Run 为什么未提交；
- 任意未知项都有明确处理动作；
- Manager 候选结果不会绕过最终确认；
- 重启后恢复页和报告与之前一致；
- 已提交/已完全回滚 Run 的完整材料 7 天后按策略清理。
