# 阶段二：工作区事务与保存点

## 目标

让文件修改从真实工作区隔离出来，支持节点级回滚、Workflow 级回滚、保存点和最终冲突处理，同时保护 Workflow 启动前已有的用户修改。

## 工作区模型

### 1. 基线冻结

启动时创建 `baselineId`，记录：

- 受治理文件清单；
- 每个文件的类型、大小、mtime、内容 hash；
- Git HEAD、分支和工作区状态（如果存在 Git）；
- 未跟踪但纳入范围的文件；
- 排除路径及排除理由。

默认治理 Git 已跟踪文件和未被明确排除的用户文件；`.git`、依赖、缓存和特殊文件默认排除并只读。启动页展示纳入和排除范围。

### 2. 隔离执行目录

隔离实现可以使用临时 Git worktree，也可以使用内容快照加复制目录。当前实现对 Git 和非 Git 工作区统一使用内容快照加物理复制，以保证 dirty、未跟踪和删除状态与启动瞬间完全一致；manifest 仍记录 Git HEAD、分支和状态。未来若改用 worktree，创建流程必须是：

```text
扫描真实工作区并冻结 baseline snapshot
→ 从当前提交创建隔离 worktree
→ 将 baseline 中的 dirty 修改、未跟踪文件和删除状态物化到隔离 worktree
→ Agent/脚本只使用物化后的隔离目录
```

Agent 和脚本的当前工作目录必须指向隔离目录，不能把原始 worktree 当作 dirty 基线。

隔离目录包含：

- `baseline/`：只读基线；
- `workspace/`：节点实际执行目录；
- `snapshots/{savepointId}/`：保存点快照；
- `reports/`：diff、校验和恢复报告。

真实工作区在运行期间只读监测，不接受 Workflow 直接写入。所有路径在打开、写入、删除和提交前都必须解析并验证位于治理根目录内；符号链接、junction 和跨盘映射默认只读，发现路径逃逸立即暂停。

### 3. 节点级保存点

每次节点 attempt 开始前创建保存点，绑定 `nodeId`、`attempt` 和创建时已有的 operationId 集合。节点重试必须恢复该保存点，再开启新 attempt；节点继续执行不得恢复，但必须向上下文注入当前 diff、已完成操作和禁止重复操作。用户发起的保存点回滚只针对当前保存点；若无法证明保存点后没有新增外部操作，恢复页不提供该动作，避免只恢复文件而遗漏外部副作用。

### 4. 提交

Workflow 全部通过后进入 `committing`：

1. 重新扫描真实工作区；
2. 与基线做三方比较；
3. 无用户并发修改时应用隔离区 diff；
4. 有冲突时进入 `waiting_for_user`；
5. 用户确认最终 diff 后原子替换或按文件安全应用。

提交计划必须绑定变更路径以及每个变更文件提交前后的内容 hash。审批后即使路径集合不变，只要文件内容发生变化，原计划也必须失效；协调器在产生任何副作用前核验证据摘要，并在真正应用文件前再次核验。第二次核验失败时，已执行的可撤销外部操作进入补偿，未核验的文件内容不得提交。

## 回滚

- 隔离区内回滚：恢复快照或删除隔离目录；
- 已提交到真实工作区的文件：根据基线生成反向 patch；
- 用户并发修改：禁止覆盖，生成三方冲突报告；
- 全量回滚：优先丢弃隔离区；跨提交点时逐项执行外部补偿并记录未恢复项。

## 失败处理

预检发现磁盘不足、路径无法快照或隔离环境不可用时直接阻止启动。禁止运行到一半才自动切换为真实工作区执行。

并行节点发生失败、暂停或 `unknown` 时，调度器必须停止发放新的节点任务，并向运行中的节点发送取消请求。取消完成前保留其隔离区和操作账本；无法确认进程已停止时，事务进入 `recovery_required`。

## 验收

- 启动前 dirty 文件保持不变；
- Agent 和脚本无法写入真实工作区；
- 节点重试不会重复保留上一 attempt 的文件变更；
- 用户并发编辑能被三方差异识别；
- 全量回滚后，受治理文件恢复到基线，排除项未被误删；
- 应用崩溃后仍可找到隔离区和保存点。
