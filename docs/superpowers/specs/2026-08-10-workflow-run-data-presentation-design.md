# Workflow Run 内容展示设计

## 目标

让 Run 面板中的输入、输出与 Agent 过程更像可读内容，而不是调试数据。保持当前轻量浮层、默认折叠和点击展开行为，不增加新的配置项或嵌套面板。

## 视觉方向

沿用 Session 摘要和 Memory 事实列表的内容优先风格：细分隔线、克制的字段标签、正文排版，不使用表格、大块底色卡片或 JSON 代码框。

输入与输出仍各占一个折叠区。展开后，每个顶层字段是一段连续内容：

- 字段名作为弱化的小标题。
- 文本保留自然段和换行，使用正文排版。
- 数组按顺序展示为独立条目；对象数组的每一项直接展示其可读属性，不暴露 JSON 标点。
- 普通对象按属性行展示，最多呈现实际数据已有的层级，不制造新的折叠或卡片嵌套。
- 数字、布尔值和空值使用简洁的单值样式。

字段之间仅使用细分隔线。长内容在面板内部滚动，不能撑破浮层宽度。

## 流式过程

Agent 的文本增量继续即时出现。工具调用标记一次内容边界；下一段文本到来时插入一个空行，使“检查文件”“读取配置”“汇总结论”等步骤自然分段。连续 token 仍原样拼接，不按 token 强制换行，也不把分隔符写入最终结构化输出。

## 输出语言

Workflow Agent 与 Review 节点默认使用简体中文输出，包括过程说明和结构化字段中的自然语言内容。节点目标、指令或约束明确要求其他语言时，以节点要求为准。JSON 字段 key、代码、命令、路径和专有名称保持原值。

## 数据与错误边界

本次只改变展示和 Prompt，不改变 Workflow 输出字段结构、校验规则与数据库内容。无法识别的值降级为安全文本；输出校验错误继续在现有错误区域显示。

## 验证

- 单元测试覆盖工具调用前后文本的段落分隔，并确认连续文本增量不会被拆开。
- Prompt 测试覆盖默认中文和显式语言要求可覆盖默认值的文案。
- 渲染测试覆盖文本段落、标量列表和对象列表的内容化展示。
- 保留默认折叠行为；按用户要求，不为默认折叠和点击展开本身新增测试。
