# Pi Agent 会话索引设计

## 目标

在稳定版与升级版会话应用中增加可选的 Pi Agent 会话来源。用户开启“包含 Pi 会话”后，AgentRecall 只读扫描 Pi 保存的本地会话，支持搜索、查看和现有导出能力；默认关闭，不改变未选择该来源的用户行为。

## 真实格式依据

实现以 `@earendil-works/pi-coding-agent` 0.83.0 和 Pi 源码提交 `74caa2649f10ed71b4378ce69f5d9fbfd2466ca5` 为依据。

隔离环境中的三轮真实会话确认：

- Pi 默认将会话保存在 `~/.pi/agent/sessions/<cwd 编码目录>/<时间>_<session-id>.jsonl`，需要递归扫描。
- 文件首行 `session` 保存 v3 版本、会话 ID、创建时间和 cwd。
- 后续记录通过 `id` 和 `parentId` 组成分支树；每次续聊追加在同一个文件中。
- 最新的 `session_info.name` 是当前标题，空名称会显式清除自定义标题；没有有效名称时回退到第一条非空用户文本。
- `message` 记录保存角色、内容、消息时间、模型和 token 用量。
- Pi 在产生第一条 assistant 回复后才创建会话文件，因此磁盘上不会出现仅有未回复输入的新会话。

## 方案选择

采用 AgentRecall 内部的专用 Pi 解析器，不引入 Pi 运行时依赖。

未采用的方案：

- 按 JSONL 行序直接使用通用解析器：实现较小，但会把用户回退分支后废弃的消息混入当前上下文。
- 直接调用 Pi 的 `SessionManager`：可复用上游逻辑，但会增加运行时依赖，并可能执行 Pi 的版本迁移或持久化行为，不符合只读索引边界。

## 来源注册与设置

- 新增 `pi` 会话格式、`pi-cli` 会话来源和 `pi` 来源族。
- 新增 `includePi` 可选设置，默认值为 `false`。
- V1 和 V2 设置页都显示“包含 Pi 会话”开关。
- 开启后，默认索引刷新递归扫描 `<homeDir>/.pi/agent/sessions/**/*.jsonl`；关闭后不访问该目录。
- Pi 不接入当前会话进程检测、远程同步、会话迁移或恢复按钮。Issue 范围仅包括本地索引、搜索、查看和导出。

## 解析与数据流

1. 逐个读取递归发现的 JSONL 文件，并记录文件修改时间用于增量索引。
2. 单行 JSON 解析失败时忽略该行；缺少有效 `session` header、会话 ID、cwd 或消息内容的文件不产出会话。
3. v2/v3 记录从文件最后一条带 ID 的记录开始，沿 `parentId` 回溯到根，再反转为当前活跃分支。检测到循环或断裂父链时跳过该文件，避免把不确定的分支拼成错误上下文。
4. v1 或没有父子字段的记录按文件顺序作为线性会话读取。
5. 只将活跃分支中的 user 和 assistant 消息用于可见上下文；thinking 内容不进入搜索正文。文本块进入消息正文，Pi 的 base64 图片块复用现有附件表示。
6. assistant 的 toolCall 和后续 toolResult 转换为 AgentRecall 工具事件，使会话详情保留工具调用上下文；toolResult 不重复进入可见消息，未知的 custom 记录保持忽略。
7. 标题遵循最后一条 `session_info`：名称非空时使用该名称，名称为空时视为显式清除；最终没有自定义名称时使用第一条非空用户文本。
8. 会话开始时间来自 header，每条消息保留自身时间戳；文件 mtime 作为现有活动排序和增量索引信号。
9. token 统计累计文件中所有有效 assistant 消息的用量，反映实际已发生的调用成本。Pi 的 `reasoning` 是 `output` 子集，因此映射时从普通输出中扣除 reasoning；`cacheRead` 与 `cacheWrite` 合并为缓存 token。
10. 产出的标准 `IndexedSession` 进入现有索引、搜索、详情和导出链路，不新增专用导出实现。

## 双版本边界

- V1 使用现有同步 SQLite 索引路径。
- V2 同时接入同步默认加载器与 PostgreSQL 异步默认加载器。
- 两个版本共享同一产品语义和测试场景，但分别在各自现有 loader 结构中实现，不跨应用引入新的共享运行时依赖。

## 错误处理

- Pi 根目录不存在、不可读或为空时返回空结果。
- 单个文件损坏、父链循环或 header 无效时只跳过该文件，继续索引其他会话。
- 单行未知记录类型保持前向兼容并被忽略。
- 所有读取保持只读，不修改、迁移或重写 Pi 文件。

## 验证

- 使用基于真实 Pi 0.83.0 三轮会话结构的合成 fixture，验证递归扫描、标题覆盖、cwd、时间、消息和 token 映射。
- 构造带废弃兄弟分支的 v3 fixture，验证只展示最后叶节点所在的活跃分支。
- 覆盖 v1 线性记录、图片、工具调用与结果、未知记录、坏 JSON、父链循环、缺失目录和默认关闭行为。
- V1、V2 分别先运行失败测试，再完成实现并运行对应 loader、来源注册、设置默认值和设置界面测试。
- 运行类型检查、`npm run release-note:check`、仓库测试与构建；测试只使用临时 HOME 和合成数据。
