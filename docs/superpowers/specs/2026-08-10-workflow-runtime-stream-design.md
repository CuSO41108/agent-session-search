# Workflow Runtime 流式输出

## 目标

Workflow 执行 Agent 节点时，选中该节点即可在 Run 检查面板实时看到 Runtime 的文本输出，无需等待节点完成。

## 数据流

Runtime 已产生标准化的 `delta` 事件。Workflow Agent 执行器把这些事件标记为 `runId + nodeId`，主进程通过专用 Electron IPC 事件推送到 renderer；preload 仅暴露订阅与退订接口。页面在内存中按 Run 和节点累加文本，不把 token 增量写入 PostgreSQL。

节点最终响应仍按现有流程解析、校验并持久化为结构化输出。应用刷新后，执行中的临时文本可以丢失，已完成的结构化输出必须保留。

## 界面

Run 检查面板把扁平的“实时输出”区域固定在节点标题和尝试次数之后、输入详情之前，避免长输入把运行反馈推到可视区域之外。Agent 或 Review 节点一进入 `running`，该区域立即出现，并在首个增量到达前显示等待提示；收到增量后在原位用等宽文本持续追加并保留换行。

暂停、取消或失败不会清空当前页面已收到的文本，重新启动或重试同一节点时清空旧文本。Script 和 Approval 节点不显示无意义的流式等待区域。

## 边界与错误

- 第一版只推送用户可读的 `delta` 文本，不展示系统事件、工具调用或内部推理。
- IPC 推送失败不能影响 Workflow 执行或最终结果。
- 页面卸载时必须退订，避免重复监听。
- 多节点并行执行时，增量必须严格归属对应 Run 与节点。

## 验证

- Agent 执行器测试确认 `delta` 被转成带 Run/节点身份的流事件，同时最终 JSON 仍正常解析。
- IPC 与 preload 测试确认订阅、推送和退订契约。
- renderer 测试确认流文本逐段追加、节点重试时清空，并且不会与其他节点串流。
- UI 测试确认运行中的 Agent 节点在首个增量前也显示等待状态，且实时输出位于输入详情之前。
