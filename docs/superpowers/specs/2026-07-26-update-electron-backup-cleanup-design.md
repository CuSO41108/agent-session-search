# Electron 更新备份清理容错设计

## 目标

修复应用内更新已经准备好可用 Electron 运行时后，因清理旧运行时备份持续返回 `ENOTEMPTY` 而把整个更新判定为失败的问题。

本次只处理截图中的备份清理失败，不恢复发布包内置 Electron，不改变下载、校验、回滚、原子替换或更新界面流程。

## 方案选择

采用“验证成功后隔离旧备份，再非阻塞清理”的方案：

- 新 Electron 运行时仍须通过现有完整校验。
- 校验成功后，把旧 `dist` 和 `path.txt` 备份原子移动到待安装包外的临时清理目录。
- 清理临时目录时继续使用现有重试逻辑；重试耗尽只留下临时目录，不再推翻已经成功的运行时校验。
- 更新失败且新运行时不可用时，仍从原备份位置恢复，保持现有回滚语义。

未采用的方案：

- 仅延长 `ENOTEMPTY` 重试：只能降低概率，超时后仍会误判更新失败。
- 忽略包内备份清理错误：会把可能很大的旧 Electron 运行时随新包安装到正式目录。
- 恢复发布包捆绑 Electron：增加下载体积和旧兼容复杂度，也不能消除目录清理错误。

## 数据流与错误处理

1. `ensureInstalledElectron` 保存当前 `dist` 和 `path.txt`，并执行现有修复。
2. 修复后的运行时通过版本、可执行文件和完整性校验。
3. 旧备份被移动到 `packagePath` 的同级临时目录，确保不会随待安装包进入正式目录。
4. 更新器尝试删除该目录；`ENOTEMPTY` 等瞬时错误在现有重试耗尽后降级为残留清理，不影响更新成功。
5. 若步骤 2 未成功，仍恢复原备份并返回真实的运行时安装错误。

## 测试

- 新增回归测试，模拟旧运行时损坏、修复成功以及备份目录每次删除都返回 `ENOTEMPTY`。
- 断言 `ensureInstalledElectron` 成功返回，新运行时可用，包内不残留 `.backup` 目录。
- 保留现有“短暂 `ENOTEMPTY` 后重试成功”和“修复失败后恢复旧运行时”测试。
- 运行脚本测试、完整测试、类型检查、构建、release note 检查和 package smoke。
