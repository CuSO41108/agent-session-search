# 按轮次迁移 Session

## 目标

用户可以在 Session 详情中右键某一轮并选择“迁移”。目标 Session 包含第一轮至所选轮次的用户与助手消息，所选轮次之后的内容不参与迁移。现有的整段 Session 迁移入口继续保留。

同时，将判断“完整迁移”还是“压缩迁移”的固定阈值从 60K Token 提高到默认 100K Token，并允许用户在设置中调整。

## 交互

- 普通 Turn 卡片响应右键操作，并显示一个只有“迁移”的菜单。
- 前置轨迹不是用户对话轮次，不显示迁移菜单。
- 点击“迁移”后复用现有目标 Runtime 选择弹窗。
- 弹窗明确显示“包含至第 N 轮，之后的内容不会迁移”。
- 不支持迁移的来源和远程 Session 不提供按轮次迁移操作。
- 选择最后一轮时，迁移内容与整段 Session 迁移一致。

## 迁移边界

Renderer 只提交稳定的 `turnId`，不提交消息序号。主进程必须：

1. 验证 Turn 存在并属于当前 Session。
2. 拒绝前置轨迹或没有有效消息边界的 Turn。
3. 以该 Turn 中最大的源消息序号为截止位置。
4. 仅将截止位置以内的消息送入现有迁移流程。

后续消息必须在压缩、摘要或目标格式写入之前移除，避免它们进入迁移摘要。

## 完整迁移阈值

新增设置 `migrationCompleteTokenLimit`：

- 默认值：`100_000`
- 设置页名称：`完整迁移阈值`
- 界面单位：`K Token`
- 默认输入值：`100`
- 步长：`10K`
- 允许范围：`10K` 至 `1,000K`
- 非数字或越界值在设置合并时规范到允许范围；无法解析时恢复默认值。

Token 数量继续沿用当前迁移链路的近似估算。所选迁移内容的估算值不超过阈值时完整迁移；超过阈值时继续使用现有的 AI 压缩和本地裁剪回退。本次不修改长 Session 的压缩内容结构。

该设置统一应用于桌面 Session 迁移、远程 Session 恢复和 MCP 迁移，避免同一用户配置在不同入口表现不一致。

## 数据流

1. 用户右键 Turn 并选择“迁移”。
2. Renderer 保存 `{ session, throughTurnId, throughTurnIndex }`，打开现有迁移弹窗。
3. 用户选择目标 Runtime。
4. Preload 向主进程发送结构化迁移请求，其中 `throughTurnId` 可选。
5. 主进程加载 Session 与全部消息；存在 `throughTurnId` 时验证并截断消息。
6. 迁移服务读取 `migrationCompleteTokenLimit`，选择完整或压缩策略。
7. 目标 Session 写入、索引和启动继续复用现有流程。

整段迁移不携带 `throughTurnId`，行为保持不变。

## 错误处理

- Turn 不存在或属于其他 Session：拒绝迁移并显示错误。
- 前置轨迹或没有有效消息边界：拒绝迁移。
- 设置值无效：使用规范化后的安全值，不让迁移请求失败。
- 迁移后的索引或启动失败：继续沿用现有警告和 Resume 命令回退。

## 测试

- 设置默认值为 100K Token，并覆盖合法值、越界值和无效值的规范化。
- 100K 以下使用完整迁移，超过 100K 使用压缩策略。
- 自定义阈值会传入本地、远程和 MCP 迁移入口。
- 按中间 Turn 迁移时只保留该 Turn 及之前的消息。
- 最后一轮迁移等同整段迁移。
- 拒绝跨 Session、前置轨迹和无消息边界的 `turnId`。
- Turn 右键菜单只显示“迁移”，并将正确的 `turnId` 传给迁移请求。
- 迁移弹窗正确说明截止轮次。
