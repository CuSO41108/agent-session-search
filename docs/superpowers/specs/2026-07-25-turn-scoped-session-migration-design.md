# 按轮次迁移 Session

## 目标

用户可以在 Session 详情中右键某一轮并选择“迁移”。目标 Session 包含第一轮至所选轮次的用户与助手消息，所选轮次之后的内容不参与迁移。现有的整段 Session 迁移入口继续保留。

同时，将判断“完整迁移”还是“压缩迁移”的固定阈值从 60K Token 提高到默认 100K Token，并允许用户在设置中调整。

## 交互

- 普通 Turn 卡片响应右键操作，并显示一个只有“迁移”的菜单。
- 前置轨迹不是用户对话轮次，不显示迁移菜单。
- 点击“迁移”后复用现有目标 Runtime 选择弹窗。
- 弹窗明确显示“包含至第 N 轮，之后的内容不会迁移”。
- 不支持迁移的来源和远程 Session 不提供按轮次迁移操作。
- 选择最后一轮时，迁移内容与整段 Session 迁移一致。

## 迁移边界

Renderer 只提交稳定的 `turnId`，不提交消息序号。主进程必须：

1. 验证 Turn 存在并属于当前 Session。
2. 拒绝前置轨迹或没有有效消息边界的 Turn。
3. 以该 Turn 中最大的源消息序号为截止位置。
4. 仅将截止位置以内的消息送入现有迁移流程。

后续消息必须在压缩、摘要或目标格式写入之前移除，避免它们进入迁移摘要。

## 完整迁移阈值

新增设置 `migrationCompleteTokenLimit`：

- 默认值：`100_000`
- 设置页名称：`完整迁移阈值`
- 界面单位：`K Token`
- 默认输入值：`100`
- 步长：`10K`
- 允许范围：`10K` 至 `1,000K`
- 非数字或越界值在设置合并时规范到允许范围；无法解析时恢复默认值。

Token 数量继续沿用当前迁移链路的近似估算。所选迁移内容的估算值不超过阈值时完整迁移。

超过阈值时只使用该阈值派生内部预算，不增加其他用户设置：

- 最近原文预算为完整迁移阈值的 50%。
- 迁移摘要预算为完整迁移阈值的 20%。
- 从所选 Turn 开始向前累加完整 Turn；加入下一轮会超过最近原文预算时停止。
- 已纳入的后缀作为最近历史原样保留，剩余的时间前缀作为早期历史生成结构化迁移摘要。
- 所选 Turn 优先完整保留；它可以单独超过最近原文预算，但不能超过完整迁移阈值。
- 如果所选 Turn 本身超过完整迁移阈值，停止迁移并提示用户提高阈值。

默认阈值为 100K Token 时，最近完整原文最多约 50K，结构化摘要最多约 20K，最终迁移内容通常不超过约 70K。用户将阈值改为 200K 时，两个内部预算自动变为 100K 和 40K。

结构化摘要必须覆盖用户原始目标、已完成工作、关键决定及原因、修改文件、错误与修复、用户纠正、当前状态和未完成事项。

早期历史沿用现有的两阶段分片压缩思路，但改为按估算 Token 和完整 Turn 划分：

1. 以完整迁移阈值的 35% 作为目标分片大小。
2. 所需分片数量为早期历史估算 Token 除以目标分片大小后向上取整；结果为 1 至 4 时继续，超过 4 时停止迁移。
3. 在不拆开 Turn 的前提下，将连续历史尽量均匀地分配到这些分片。
4. 各分片并行提取用户要求与纠正、关键决定、完成事项、文件与产物、当前问题和未完成事项；每片输出最多约 2K Token。
5. 全部分片成功后，按时间顺序将分片结果一次性合并成最终结构化迁移摘要。

默认阈值为 100K Token 时，目标分片大小约 35K；130K 的早期历史会生成约 4 个分片。实际并发数取分片数量与现有迁移压缩并发设置中的较小值，因此最多同时运行 4 个分片任务。

分片摘要彼此独立，不把上一片摘要带入下一片，不使用滚动摘要。最终合并只执行一次；合并结果不会再次进入下一层摘要。如果早期历史需要超过 4 个目标大小的分片才能安全处理，停止迁移并提示用户提高完整迁移阈值；第一版不为异常超长历史增加多层压缩。

本地 Session 使用已经索引的 Turn 边界。只有可移植消息序列的远程恢复和 MCP 入口以每条用户消息作为新 Turn 的起点，将其后的助手消息归入同一 Turn，保证同一套预算策略可以应用于所有入口。

长 Session 压缩只使用用户在设置中明确选择的总结模型。没有配置总结模型或总结失败时停止迁移并显示可操作错误，不再静默调用 Codex，也不再用本地字符裁剪悄悄丢弃内容。

该设置统一应用于桌面 Session 迁移、远程 Session 恢复和 MCP 迁移，避免同一用户配置在不同入口表现不一致。

## 数据流

1. 用户右键 Turn 并选择“迁移”。
2. Renderer 保存 `{ session, throughTurnId, throughTurnIndex }`，打开现有迁移弹窗。
3. 用户选择目标 Runtime。
4. Preload 向主进程发送结构化迁移请求，其中 `throughTurnId` 可选。
5. 主进程加载 Session 与全部消息；存在 `throughTurnId` 时验证并截断消息。
6. 迁移服务读取 `migrationCompleteTokenLimit`，选择完整或压缩策略。
7. 目标 Session 写入、索引和启动继续复用现有流程。

整段迁移不携带 `throughTurnId`，行为保持不变。

## 错误处理

- Turn 不存在或属于其他 Session：拒绝迁移并显示错误。
- 前置轨迹或没有有效消息边界：拒绝迁移。
- 所选 Turn 本身超过完整迁移阈值：拒绝迁移并提示提高设置值。
- 早期历史需要超过 4 个目标大小的分片：拒绝迁移并提示提高完整迁移阈值。
- 长 Session 没有总结模型或总结失败：拒绝迁移，不创建不完整的目标 Session。
- 任一分片提取或最终合并失败：拒绝迁移，不创建不完整的目标 Session。
- 设置值无效：使用规范化后的安全值，不让迁移请求失败。
- 迁移后的索引或启动失败：继续沿用现有警告和 Resume 命令回退。

## 测试

- 设置默认值为 100K Token，并覆盖合法值、越界值和无效值的规范化。
- 100K 以下使用完整迁移。
- 超过 100K 时从所选 Turn 向前按完整 Turn 累加最近 50K 原文，其余内容生成最多 20K 的结构化摘要。
- 自定义阈值会同比调整 50% 最近原文预算和 20% 摘要预算。
- 所选 Turn 可超过最近原文预算，但超过完整迁移阈值时拒绝迁移。
- 早期历史按完整迁移阈值的 35% 计算目标分片大小，生成 1 至 4 个连续且不拆开 Turn 的分片。
- 分片任务最多 4 个并行运行，所有结果按原始时间顺序参与一次最终合并。
- 不将上一片摘要带入下一片，也不进行滚动或递归摘要。
- 需要超过 4 个目标分片时拒绝迁移。
- 长 Session 缺少总结模型或总结失败时不创建目标 Session。
- 自定义阈值会传入本地、远程和 MCP 迁移入口。
- 按中间 Turn 迁移时只保留该 Turn 及之前的消息。
- 最后一轮迁移等同整段迁移。
- 拒绝跨 Session、前置轨迹和无消息边界的 `turnId`。
- Turn 右键菜单只显示“迁移”，并将正确的 `turnId` 传给迁移请求。
- 迁移弹窗正确说明截止轮次。
