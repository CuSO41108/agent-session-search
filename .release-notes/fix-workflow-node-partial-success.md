# Workflow 安全执行与运行历史升级

## 新增功能

- 新建 Workflow 默认使用严格原子事务；运行会保存事务模式、操作状态与恢复风险，重启后仍能识别这些记录。严格事务会在隔离工作区内执行，并在工具调用、脚本结果、结构化输出和文件变化全部通过验收后安全应用变更。工具失败、脚本警告或副作用状态未知不再被成功文本掩盖，遇到用户并发编辑或未知外部状态时会保留现场并等待恢复。
- Run Center 现在会展示三方冲突、外部操作凭据、只读恢复建议和风险对比；用户确认后可继续、回到保存点或尽力补偿可撤销操作，并可下载最终报告、安全清理已提交或已完全回滚的本地材料。
- 打开 Run Center 时会重新核对状态未知的外部操作，并由 Manager Agent 基于节点历史、文件差异和操作凭据生成只读恢复建议；文件冲突可逐项保留当前版本、采用 Workflow 结果或手动合并，最终写入前会再次展示内容并确认。
- 新增“代码变更审查”官方 Workflow，可收集指定目录内已暂存、未暂存和未跟踪的 Git 变更，并行检查正确性、安全性、测试和兼容性风险，最终生成带代码证据的中文报告。
- Workflow 运行历史可按状态、触发来源、日期和图版本筛选，并查看节点消息、工具调用、审批、输入输出、Runtime、模型、真实 Token 用量和安全产物预览；应用重启后这些记录仍可继续查看。
- Runtime、MCP、Workflow 和 Agent 评测能力现在可直接在应用内配置与使用，可信本地 Agent 可在授权范围内确认、启动、查询和介入 Workflow。

## Bug 修复

- 修复 Workflow 节点执行本地命令时跳过授权确认的问题；运行会显示审批卡片，并在用户允许或拒绝前保持等待。
- 修复 Agent 持续输出或节点频繁更新时 Workflow 页面偶发卡顿的问题，长回复与较多运行历史下的交互更加流畅。
- 修复 Workflow 节点成功文本掩盖工具失败、脚本警告或未知副作用的问题；未通过完整验收的节点不会继续推动下游执行。
