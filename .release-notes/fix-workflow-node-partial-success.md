# Workflow 安全执行与运行历史升级

## 新增功能

- 新建 Workflow 默认使用严格原子事务；运行会保存事务模式、操作状态与恢复风险，重启后仍能识别这些记录。严格事务会在隔离工作区内执行，并在工具调用、脚本结果、结构化输出和文件变化全部通过验收后安全应用变更。工具失败、脚本警告或副作用状态未知不再被成功文本掩盖，遇到用户并发编辑或未知外部状态时会保留现场并等待恢复。
- Run Center 现在会展示三方冲突、外部操作凭据、只读恢复建议和风险对比；用户确认后可继续、回到保存点或尽力补偿可撤销操作，并可下载最终报告、安全清理已提交或已完全回滚的本地材料。
- 外部操作状态无法自动确认时，Run Center 现在允许用户依据远端记录核验为“已应用”或“未应用”；核验人、理由和结果会保存到事务记录，并立即刷新后续恢复选择。
- 严格 Workflow 现在会执行定义中的保存点和提交点：必审提交点会展示当前计划摘要并保留现场等待确认，文件或外部操作变化后会要求重新确认；阶段提交可在确认后继续后续节点，Run Center 同时展示待审批检查点、已完成检查点、实际纳入事务的文件数和排除路径。
- 打开 Run Center 时会重新核对状态未知的外部操作，并由 Manager Agent 基于节点历史、文件差异和操作凭据生成只读恢复建议；文件冲突可逐项保留当前版本、采用 Workflow 结果或手动合并，最终写入前会再次展示内容并确认。
- 新增“代码变更审查”官方 Workflow，可收集指定目录内已暂存、未暂存和未跟踪的 Git 变更，并行检查正确性、安全性、测试和兼容性风险，最终生成带代码证据的中文报告。
- Workflow 运行历史可按状态、触发来源、日期和图版本筛选，并查看节点消息、工具调用、审批、输入输出、Runtime、模型、真实 Token 用量和安全产物预览；应用重启后这些记录仍可继续查看。
- Runtime、MCP、Workflow 和 Agent 评测能力现在可直接在应用内配置与使用，可信本地 Agent 可在授权范围内确认、启动、查询和介入 Workflow。

## Bug 修复

- 修复 Workflow 节点执行本地命令时跳过授权确认的问题；运行会显示审批卡片，并在用户允许或拒绝前保持等待。
- 修复 Agent 持续输出或节点频繁更新时 Workflow 页面偶发卡顿的问题，长回复与较多运行历史下的交互更加流畅。
- 修复 Workflow 节点成功文本掩盖工具失败、脚本警告或未知副作用的问题；未通过完整验收的节点不会继续推动下游执行。
- 修复多个 Workflow 同时向同一工作区提交时可能越过并发检查的问题；提交、冲突写入和回滚现在会串行处理，后到的冲突不会覆盖先完成的结果。
- 修复暂停节点后立即继续时偶发提示运行仍在进行的问题；暂停操作会在旧执行完全退出后再允许恢复。
- 修复同时执行多个恢复或人工核验操作时可能互相覆盖记录的问题；同一运行的恢复请求现在按顺序处理，并会等待当前执行完全停止后再修改恢复状态。
- 修复严格 HTTP 操作携带敏感凭据时直到审批后才失败的问题；此类计划现在会在执行前明确拒绝，避免形成无法安全恢复的操作。
- 修复应用重启或执行恢复操作后最终报告可能退化、缺少最新证据的问题；真实文件差异、脱敏请求与回执、补偿结果、人工核验和冲突决定会随运行记录保留。
- 修复回滚保存点时可能只恢复文件、遗漏保存点后外部操作的问题；系统现在会记录保存点的操作边界，无法安全证明一致性时不再提供该回滚动作。
- 修复恢复时间较长的运行在刚完成后可能立即清理事务材料的问题；最终提交、完整回滚和人工恢复会从最近活动时间重新计算保留期限。
- 修复提交点审批后同一路径文件内容变化仍可能沿用旧授权，以及冲突处理中选择当前版本或手动合并后无法完成提交的问题；提交计划现在绑定文件内容，并会把已确认的冲突结果纳入新计划，其他内容或外部操作发生变化时仍会停止并要求重新确认。
- 修复恢复页在没有剩余节点或待审批提交点时仍显示“继续”的问题；页面和恢复建议现在只提供后端实际可执行的动作。
- 修复应用重启后纯文件变更偶尔不再显示全量补偿动作的问题；恢复页现在会保持与重启前一致的工作区恢复能力。
- 修复隔离工作区或保存点材料已经丢失时恢复页仍可能显示“继续”或“回到保存点”的问题；系统现在会先核验本地恢复材料，只展示真正可执行的动作。
- 修复文件回滚成功但仍有不可撤销外部操作时，运行可能误报为完全回滚的问题；现在会明确显示“部分回滚”，保留未恢复操作及所需人工处理步骤。
- 修复应用重启后新出现的文件冲突可能未被恢复页识别，或同一路径内容变化后仍沿用旧恢复建议的问题；系统现在会重新核对三方文件内容，并在证据变化时撤销过期建议。
- 修复恢复页打开后再修改其他文件，或外部操作记录无法读取时，仍可能错误允许继续的问题；执行任何恢复动作前都会重新核对全部文件冲突和操作证据，无法确认时保留现场。
- 修复严格 Workflow 在隔离工作区准备失败后，运行历史缺少失败阶段和原因的问题；现在会在任何节点启动前停止，并保存脱敏后的预检失败记录。
