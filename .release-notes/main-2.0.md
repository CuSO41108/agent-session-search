# 全新工作台首页

## 新增功能

- 新增“代码变更审查”官方工作流，可收集 Git 变更并从正确性、安全性、测试和兼容性角度生成带代码证据的中文报告。
- 启动后可在三段式总览中直接查看会话、消息、Token 构成、缓存率和来源用量；Codex 与 Claude Code 额度并列显示并可统一刷新。
- 工作台新增近 7 天 Token 折线，可查看每天的输入、缓存、输出和推理用量，并从任意日期直接筛选当天活跃的会话。
- 工作台用可滚动列表集中展示 10 条会话，活跃会话优先并明确标出 Open 或 Closed，可直接搜索、打开详情或一键 Resume。
- 工作台、会话、Skills 和 Provider 使用统一的标题栏；完整筛选与配置迁移到各自页面，并移除会话页重复的设置入口。
- Session 搜索会定位到命中的具体对话轮次，展示关键词附近的上下文，同时仍以完整 Session 作为打开、筛选和 Resume 的入口。
- Session 页面新增高级搜索、命名搜索和结果分组，可组合来源、标签、时间及可见性条件，并在详情中查看相关会话。
- Session 详情可将会话导出为 OpenAI Chat Completions、OpenAI Responses 或 Anthropic Messages 请求体；Codex 会话会尽可能保留模型、指令、工具调用、工具结果和推理参数，并标明导出内容来自原始记录、历史重建还是标准化转换。
- Skills 页面将本 App Skill 与本地 Skill 分为两个 Tab：本地 Skill 按使用量优先排列，可直接预览并加入本 App；发现入口支持榜单、关键词和一次性 AI 搜索，安装位置改为可扩展的 Agent 多选弹窗，原目录与同名冲突目录不会被覆盖。
- Skill 的 AI 探索可在设置中选择指定 Runtime，也可自动使用首个可用配置；普通榜单仍在加载时也能立即发起探索。
- Skill 使用次数、云端同步、版本恢复和文件差异集中到所选 Skill 的详情中；应用冷启动、托盘打开和普通唤起默认停留在工作台，只有搜索快捷键会进入会话搜索。
- 🧠 Memory 页面升级为基于 OpenViking 的目录级长期记忆：默认关闭，只处理用户主动选择的目录，并为每个目录隔离会话、记忆与索引。
- 可在设置中按需下载托管组件和本地向量模型；CPU 即可运行，不要求独立显卡或系统 Python。
- 可分别为 Claude Code、Codex 和 OpenCode 开启自动召回与记忆；未受管理的目录不会读取对话内容，记忆不可用时也不会阻断 Agent。
- 目录记忆会自动复用当前 Codex 登录，并把 OpenViking 凭据隔离保存在 AgentRecall 中，无需单独执行鉴权初始化，也不会与独立安装的 OpenViking 共用凭据。
- 支持导入所选目录的已有会话、检索和维护记忆；停止管理会保留数据，永久删除目录记忆时会明确二次确认。
- 新增 Runtime、MCP 与 Workflow 工作区：可通过紧凑下拉切换并测试 Codex、Claude Code、API、Hermes、OpenCode 和 OpenClaw 配置，管理本地或远程 MCP 服务及工具，把自定义 MCP 按 Agent 绑定到新会话，并在应用内完成 Workflow 的创建、审核、确认、运行、暂停、人工介入和输出查看；工作台会同步展示真实 Workflow 状态并直达详情。
- 工作台将 Session、Workflow、Memory 与 Chat 统一为双列紧凑卡片，Runtime、MCP 与 Skills 排成独立一层；Session 固定预览最近 3 条会话，不再需要在卡片内滚动；各卡片可直接查看概况并进入对应页面，点击“调整布局”后仍可拖动或逐项移动，顺序会自动保存。
- Workflow 右侧新增独立的运行历史入口，可按状态、触发来源、日期和图版本筛选任意一次运行；详情以只读快照展示完整配置、并行节点时间线、执行与等待耗时、稳定错误码、人工审批、输入输出和安全产物预览，大量记录可按批加载。
- Workflow 运行历史的每个节点现在可展开查看实际使用的 Runtime、Channel、模型、尝试次数和执行耗时；Token 用量会按输入、输出、推理和缓存拆分，并区分 OpenAI 缓存输入与 Anthropic 的缓存读取、5 分钟/1 小时缓存写入，运行时提供数据时同时显示成本。
- Workflow 运行历史会采集 OpenAI、Anthropic 和直连 API 返回的真实 Token usage；Provider 未返回的字段保持未提供，不会用估算值覆盖实际数据。
- Workflow 节点在失败、重试、暂停恢复和交互式对话后仍会保留并汇总真实用量；成本没有 Provider 上报时会明确显示“未提供”。
- 修复 Codex Workflow 未显示真实 Token 用量的问题；现在会读取 Codex app-server 的独立 Token usage 通知，并保留缓存输入与推理输出拆分。
- Workflow 节点的历史消息会随运行记录持久保存；重新打开应用后，仍可在运行历史的对应节点中查看用户、Agent 与工具消息。
- Workflow Agent 现在可通过专用完成工具提交结构化节点结果，普通对话内容与下游节点数据分开处理，减少格式误判。
- 可信的本地 Agent 现在可以通过 MCP 确认、启动、查询、停止 Workflow，并处理运行中的人工介入和结构化输入；外部客户端默认保持只读。
- Workflow 节点会话现在会在主时间线中显示工具调用和结果，并明确标记结构化节点结果的提交。
- Codex、Claude Code、OpenCode、Hermes 和 OpenClaw 现在遵循一致的 Workflow MCP 权限范围；规划会话中的工具失败会直接显示调用名称、状态和原因，不再被误报为工具不存在。
- Workflow 运行结果查询现在提供安全的文件类型、大小和受限文本预览，并自动隐藏授权信息与常见密钥内容。
- 新增 Agent 评测工作区：可维护测试数据集，组合确定性规则或 LLM Judge，针对 Runtime 中的 Agent 重复运行实验，并查看每个 Case 的输出、评分理由、通过率、耗时和历史结果；评测还可关联完整 Session、单轮对话或具体执行步骤，历史记录较多时仍可按需继续加载。
- 界面视觉统一更新强调色、圆角、间距、阴影、动效和滚动条样式，在不同功能页之间切换时保持一致。
- 新增多 Agent Chat 工作室：同一个 Runtime 配置可以创建多个独立员工，分别保留并复用自己的会话；用户可明确选择一名或多名员工并行工作，任一员工运行时仍可继续向其他员工发送消息。
- 工作室员工共享同一个项目目录，并可通过可见消息主动邀请另一名员工继续处理；普通回复不会误触发其他员工，员工还可声明准备修改的相对路径，减少并行改动冲突。内置 Workflow、工作室通信与目录协作能力统一通过一个 AgentRecall MCP 提供。
- Chat 工作室标题可在对话顶部直接修改，也可选择归档或永久删除；永久删除会一并清理房间消息与员工会话。
- Windows 用户可添加 WSL 发行版，统一搜索、查看、删除和继续其中的 Codex 与 Claude Code 会话。
- Session 详情现在按每轮对话折叠展示；可同时展开多轮，按执行顺序查看该轮的消息、工具调用、结果、错误、耗时和 Token 用量，并可选择显示或隐藏工具轨迹。
- Session 详情支持从任意一轮右键发起迁移，只带走该轮及之前的历史；完整迁移阈值默认 100K Token 并可在设置中调整，超长历史会保留最近 40% 的完整轮次并用所选摘要模型压缩更早内容。

## Bug 修复

- 设置中不再显示容易误解的 Claude Code Skill Hook 开关；Skills 页面仍会使用已有统计数据，并继续自动统计 Codex 的 Skill 使用次数。
- Windows 的 WSL 会话会在后台补齐对话全文索引，文件未变化时不会重复读取，全文搜索可直接命中 WSL 中的用户与 Agent 消息。
- Cursor Session 现在只展示 Cursor 当前可见的对话分支，并自动清理已经没有可读消息的残留空会话。
- 没有项目目录的 Session 也可以上传到远程，不再被刷新流程静默遗漏。
- Session 详情中的工具调用开关会固定显示在轨迹上方，不再随第一轮对话滚出视野；切换时会明确显示“已显示”或“已隐藏”。
- 修复工作台“调整布局”按钮无法用鼠标点击的问题，按钮现在固定在标题栏右侧，并拉开总览区与功能区的层级间距；Chat 卡片现在展示真实聊天群及成员数量，可直接进入所选群聊，不再重复罗列 Runtime 员工。
- Workflow 持续输出或节点频繁更新时会传递更小的状态变化，减少输入框、下拉框和画布偶发卡顿。
- Codex 工作流节点执行本地命令时会展示待审批提示，并在用户允许或拒绝前保持等待。
- 内置官方工作流更新后会自动加载最新节点和流程定义，不再沿用旧版本内容。
- 修复在设置中隐藏 Codex 或 Claude Code 额度后，工作台仍显示对应空卡片的问题；保留的单张额度卡会自动铺满空间，全部隐藏时会显示简短说明。
- Session 不再同时提供“收藏”和“置顶”两套重复入口；收藏的 Session 会自动排在普通 Session 前，取消收藏后恢复正常排序。
- 修复打开应用时会提前加载二级页面、远程 Session 列表并启动 Chat、MCP、评测和 Agent 执行能力，导致工作台首屏变慢的问题；现在这些内容会在首次打开对应功能时再加载。
- 修复评测页指标与数据集内容重叠、彩色数字 0 容易误认以及空数据占位不一致的问题。
- Session 搜索不再扫描工具调用及其结果，只匹配用户与 Agent 的对话消息，减少大段工具输出造成的误命中和等待。
- 修复少数会话包含特殊控制字符时索引会提前中断，导致工作台用量与 Session 数量显示不完整的问题。
- 修复评估页指标与数据集内容重叠、数字零字形辨识不清的问题，并统一空数据占位显示。
- 修复新建 Chat 房间时，工作目录为空会导致“选择目录”按钮无响应的问题；现在可以正常打开目录选择器。
- 修复部分 Cursor 会话缺少实际标题或未出现在 Session 列表中的问题。
- 修复 Windows 通过 npm 安装 Codex 或 Claude Code 后，迁移会话可能误报 CLI 未安装，以及迁移后的 Codex 会话无法恢复的问题。
- 修复 WSL 连接错误提示不准确、环境名称重复显示 WSL 前缀，以及已删除会话在下次同步后重新出现的问题。
- 修复应用启动时标签列表查询失败，导致 Session 页面无法正常初始化的问题。
- 修复系统目录暂时无法读取时应用可能启动失败或把数据写入错误位置的问题，并支持通过自定义数据目录恢复启动。
- 修复部分升级场景下趋势数据暂未就绪时，工作台可能显示空白的问题。
- 修复 Token 趋势弹层可能被页面遮挡或贴近窗口边缘的问题，并自动跳过开头连续无用量的时间段。
- 修复打开 Skills 页面、切换本地 Skill 或再次进入页面时反复扫描造成的卡顿；本地内容会优先显示，手动刷新仍可主动重新扫描。
- 修复同一个 Skill 同时来自多个本机目录时列表键冲突、条目可能重复或消失的问题。
- 调整工作台用量周期选择器的位置，以紧凑下拉框归入用量标题栏，避免统计数字被挤压。
- 修复 Workflow 审核、确认和运行按钮在详情标题栏中上飘，或在较窄窗口中被挤出内容区域的问题。
- 修复 Workflow 节点完成后未经确认就自动继续的问题；现在会先展示完成提议，等待用户确认或要求修改，异常的旧会话记录也不会再导致节点详情报错。
- 修复 Workflow Agent 在工具尚未完成启动时创建会话，导致后续始终无法调用工作流工具的问题；Codex 失败时也会显示具体原因，不再只显示笼统错误。
- 修复使用第三方模型渠道的新版 Codex 在 Responses Lite 模式下丢失 Workflow MCP 工具、因而错误提示 `workflow_create` 未提供的问题。
- 修复新版 Codex 将安全的 Workflow 草稿写入误判为需人工批准并立即拒绝，导致已暴露的 `workflow_create` 仍无法执行的问题。
- Workflow Agent 遇到确实需要用户确认的工具调用时，现在会在草稿会话中显示可操作的审批卡片，不再因缺少审批界面而直接拒绝。
- Workflow 节点的结构化结果现在会在工具调用时直接可靠保存，运行与恢复不再依赖会话历史中的展示文本，较长 Markdown 也不会因摘要截断而被误判为非法输出。
- 修复要求生成文档的 Workflow 只保存结构化文本、却没有在运行产物目录生成文件的问题；Markdown 等声明为文档产物的输出现在会稳定落盘，已有 `answer_markdown` 工作流无需重建。
- 修复长回复持续输出或评测历史较多时页面明显卡顿的问题，并避免应用重启后丢失 Agent 的指令、组合关系、版本和 MCP 绑定。
- 修复 Agent 评测混入 Workflow 规划指令的问题；评测与普通会话现在都会按所选 Agent 的自身指令执行。
- 修复不支持 MCP 的 API Runtime 仍显示可绑定，以及 Agent 切换 Runtime 后旧的托管服务无法移除的问题。
- 重整 Runtime 配置页：Codex、Claude Code 等配置可从贴边侧栏直接切换，Provider、余额和测试状态集中显示；低频 Provider 列表改为可搜索弹窗，模型、插件与高级配置默认折叠，减少首屏拥挤和横向空白。
- Runtime 的“新增配置”现在会先让用户选择 Codex、Claude Code、API 等执行器类型，再创建并打开对应配置，避免新增结果被当前选中的配置类型错误限制。
- 调整 Workflow 操作布局，将审核、确认、运行和停止集中到输入框下方并统一按钮尺寸，减少标题栏拥挤，在不同窗口比例下也能保持操作位置稳定。
- Session 页面恢复可见的“更新索引”按钮，并统一导航与页标题名称，避免只能通过侧栏图标刷新。
